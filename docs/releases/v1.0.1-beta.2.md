# GW EnergyPilot v1.0.1-beta.2

**Channel:** Beta prerelease

This opt-in beta separates the two different neutral decisions used by
Automatic Control while retaining every v1.0.1-beta.1 compatibility fix.

## Separate control boundaries

- Battery Hold uses EMHASS `P_batt` and defaults to 100 W for fresh
  configurations.
- GoodWe Auto uses EMHASS `P_grid` and has a separate 1000 W default.
- Hybrid checks Battery Hold first, then GoodWe Auto, then signed PCC import or
  export through modes 9/10.
- Exact boundaries remain neutral and neither deadband is subtracted from the
  full mode-9/10 setpoint.

With the recommended settings, `P_batt = -231 W` and `P_grid = 0 W` selects
mode 1 GoodWe Auto during normal Hybrid control. EV anti-discharge remains a
higher-priority override while the EV is actively charging.

## Configuration and dashboard

Settings → EP now groups both values in one bilingual decision panel. It shows
charging/negative `P_batt` on the left, discharging/positive `P_batt` on the
right, a central `0 W` marker and the mode 10/1/8/1/9 decision bar. Overlapping
deadbands are rejected by both frontend and backend validation.

Existing installations retain their stored `deadband` value as Battery Hold;
the upgrade does not silently retune an active real-power controller. Set it to
100 W explicitly when adopting the recommended 100 W / 1000 W combination.

## Compatibility and safety

- GoodWe registers, EMS setpoint-before-mode write ordering and manual-control
  ownership are unchanged.
- The EV override uses Battery Hold for battery direction and GoodWe Auto for
  an explicit grid-import charge target.
- Execution evidence and future plan projection use the same pure two-deadband
  decision function as live control.
- Entity unique IDs, device identity, persistent Store schemas, accounting,
  EMHASS ownership and Battery Saver profiles are unchanged.
- The v1.0.1-beta.1 legacy-interval and WebKit click fixes remain included.

## Validation

The release includes exact-boundary, maximum-power, EV-override and field-case
unit regressions. The Settings → EP panel is also exercised on desktop
Chromium, iPad WebKit touch and iPhone WebKit touch, including responsive fit,
central alignment, invalid-overlap blocking and submission of both settings.

## Installation

This build is offered only to HACS users who explicitly enabled prereleases for
GW EnergyPilot or deliberately select `v1.0.1-beta.2` in the repository version
picker. Normal users remain on the latest stable release. Restart Home Assistant
after installation when HACS requests it.
