# GW EnergyPilot v1.0.1-beta.4

**Channel:** Beta prerelease

## Select one charging signal

Settings → EV now offers one explicit detection choice:

- **Charger power sensor** — charging is active when finite, unit-normalized
  measured power is above the configured watt threshold.
- **Charging status / boolean** — charging is active for `on`, `true`,
  `charging` or `connected_charging`.

Only the selected source controls EV anti-discharge. A Tesla Wall Connector can
use its `Opladen` binary sensor. A Zaptec installation can use a status sensor
that reports `connected_charging`. Plug/connectivity entities and allocated or
maximum current do not prove that the vehicle is drawing power and should not
be selected as a charging signal.

Existing entries without the new method key retain the exact historical
`connected_charging`-or-power behavior until the operator saves an explicit
choice.

## Safe recovery after charging stops

EV-stop protection still holds the home battery until a fresh EMHASS plan is
available. If the immediate optimization overlaps another cycle or fails
transiently, EnergyPilot retries after 5, 15, 30 and 60 seconds. A new charging
start cancels the pending retry; the regular wall-clock schedule remains the
fallback after the bounded sequence.

## Compatibility and safety

- No GoodWe register, EMS mode, setpoint or write ordering changes.
- No changes to non-EV Battery, Grid or Hybrid decisions.
- No unique-ID, device-identity or persistent Store-schema changes.
- EV detection remains observation-only; charger-current control stays isolated
  in the optional EV load balancer.
