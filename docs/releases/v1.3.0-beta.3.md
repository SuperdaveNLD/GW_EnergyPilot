# GW EnergyPilot v1.3.0-beta.3

**Channel:** Beta prerelease

This beta adds an explicit solar-production comparison to the detailed
Battery · Plan · Price graph. It does not change any GoodWe, EMS, EMHASS,
accounting or entity-identity behavior.

## Actual and expected solar production

The **Large** and expanded Battery · Plan · Price graph now shows:

- a solid yellow line for the actual combined PV production, using the existing
  Recorder five-minute means for `pv_generation_power`;
- a dashed yellow step line for expected solar production, using only the
  non-negative `P_PV` values from the current validated official EMHASS plan.

The two series use the same power axis as the charge/discharge display. The
forecast has no Home Assistant entity fallback and is deliberately absent when
the current plan is unavailable, uses the compatibility schedule source or
does not expose `P_PV`. It is dashboard evidence only: it never enters
Automatic Control, EMS writes, grid accounting or financial totals.

## Compatibility and safety

The existing combined PV entity, Recorder request and persistent EMHASS plan
mirror remain the only data sources. No Modbus registers, control behavior,
configuration entries, persistent Store schema or entity unique IDs change.

Stable v1.2.0 remains the normal/latest production release. This beta is
available only to users who explicitly enable prereleases for the HACS
repository.

## Validation

The release passed Python compilation, the complete repository unit suite,
repository invariant validation and a local desktop/mobile frontend harness
check. The browser regression matrix now asserts both actual and forecast solar
series in the Large chart alongside the existing source-attribution coverage.

The complete active frontend graph uses cache boundary `1.3.0-beta.3`.
