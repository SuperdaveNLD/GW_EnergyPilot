# GW EnergyPilot v1.2.0

**Channel:** Stable

This release promotes the exact v1.2.0-beta.7 runtime behavior to the normal
Home Assistant/HACS production channel. The promotion changes versioning,
release presentation and the complete frontend cache boundary; it does not
reinterpret GoodWe, EMS or EMHASS behavior.

## Mobile control reliability

- operational controls remain in one permanent declarative Lit surface;
- normal telemetry patches existing DOM instead of replacing active controls;
- the root-scoped adapter waits 120 ms for a missing native iOS touch click and
  then invokes only the same element's existing `.click()` path;
- movement beyond 12 px, pointer cancellation, secondary touches and disabled
  or disconnected controls remain rejected;
- one late physical click after fallback is deduplicated;
- graph size/range, expand/footer and execution-history open/close controls
  retain minimum 44 × 44 CSS-pixel targets on coarse-pointer or narrow screens.

## Runtime additions promoted from the beta line

- optional SEMS+ Beta telemetry remains strictly separate from local GoodWe
  EMS and verified minimum-SOC control;
- the official EMHASS plan mirror provides bounded resilience without becoming
  a second optimizer or extrapolating expired rows;
- Settings offers AUTO or horizon-aware CUSTOM fixed household load forecasting;
- Wanted-SOC history uses the active interval end and execution history keeps
  verified runtime-session evidence;
- the local Beta Tests page remains diagnostic-only and cannot call Home
  Assistant services, GoodWe or EMHASS.

## Compatibility and validation

GoodWe register definitions, EMS write order/signs, Battery Saver ownership,
entity unique IDs, device identifiers and persistent store keys are unchanged
by this promotion. The exact stable commit must pass compile, all unit tests,
repository validation, HACS, hassfest, audit and the desktop Chromium, iPad
WebKit touch and iPhone WebKit touch matrix.

The complete active frontend graph uses cache boundary `1.2.0-stable1`.
