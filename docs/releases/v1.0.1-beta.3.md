# GW EnergyPilot v1.0.1-beta.3

**Channel:** Beta prerelease

This opt-in beta makes the native EMHASS schedule resilient to Home Assistant
startup timing, corrects historical YAML migration detection and aligns the
dashboard Mapping value with the backend controller decision. Every
v1.0.1-beta.2 control-boundary change remains included.

## Restart-safe scheduling

- A wall-clock boundary reached before Home Assistant Core is running returns
  before optimization, publication or persistent failure logging.
- The delayed startup recovery follows the same Core-state gate and uses its
  existing bounded 15/30/60-second retry sequence while startup is incomplete.
- Once Home Assistant is running, the normal wall-clock owner and recovery
  behavior continue unchanged.

## Legacy YAML migration (#115)

Only an enabled
`automation.energypilot_emhass_orchestrator` is a competing recurring
scheduler. The historical `script.energypilot_emhass_optimize_now` is a manual
helper and no longer disables native scheduling by itself. A disabled legacy
automation no longer blocks native scheduling either.

The complete obsolete YAML package should still be removed after migration,
but temporarily retaining its manual script no longer leaves Automatic
Scheduling apparently enabled without an active wall-clock callback.

## Canonical dashboard mapping

The live EMHASS **Mapping** metric now consumes the controller's existing
`controller_expected_mode` and `controller_target_power` diagnostics. For
example, Hybrid `P_batt = +775 W` with `P_grid = 0 W` is shown as mode 1
GoodWe Auto instead of being reinterpreted as Battery-strategy mode 12.

Older backends that do not expose the controller diagnostics retain the
previous display-only fallback. No controller decision is made in the
frontend.

## Compatibility and safety

- GoodWe registers, EMS setpoint-before-mode write ordering and manual-control
  ownership are unchanged.
- Battery, Grid, Hybrid and EV anti-discharge decision outputs are unchanged;
  this release corrects scheduling eligibility and operator presentation.
- Entity unique IDs, device identity, persistent Store schemas, accounting,
  EMHASS ownership and Battery Saver profiles are unchanged.
- The v1.0.1-beta.2 two-deadband policy and all earlier beta fixes remain
  included.

## Validation

The release includes regressions for script-only, disabled-automation and
enabled-automation migration states, startup wall-clock boundaries, bounded
startup recovery and stable-DOM EMS mapping. The required desktop Chromium,
iPad WebKit touch and iPhone WebKit touch matrix protects the active v1.0.1
frontend graph.

## Installation

This build is offered only to HACS users who explicitly enabled prereleases for
GW EnergyPilot or deliberately select `v1.0.1-beta.3` in the repository version
picker. Normal users remain on the latest stable release. Restart Home Assistant
after installation when HACS requests it.
