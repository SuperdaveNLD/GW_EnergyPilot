# GW EnergyPilot v1.3.0-beta.9

**Channel:** Beta prerelease

**Status:** Beta; opt-in Hybrid 2.0 hardware test mapping.

## Grid-first mapping and planned watts

Hybrid 2.0 now evaluates the grid deadband first, including `P_batt = 0`.
Inside that band it uses Auto without EV. Outside it, planned battery watts
select mode 11 for charging or mode 3 for discharging. Neutral battery plans
use mode 9/10 net targets. Explicit manual Pause remains mode 8.

During EV charging, grid-neutral house self-use tests mode 5 at
`max(0, local GoodWe load 35172 - measured EV power)`, bounded by Maximum
control power and 15,000 W. The reference updates every 15 seconds through
the existing controller. External AC PV is not subtracted again. Both local
load and EV readings must be fresh within 30 seconds; cloud load and EMHASS
forecasts are not substitutes. Unusable measurements, explicit planned EV
discharge and unresolved net-only EV plans select Hold. Planned charging
outside the grid deadband follows the battery watts in mode 11 with or
without EV. Existing readiness, persistent-plan and EV-stop gates remain.

The controller is enabled by selecting **Hybrid 2.0 Beta** and enabling
Automatic Control after installation/restart. Battery, Grid and original
Hybrid behavior is unchanged. Manual mode numbers remain exact. No new
registers, charger commands, control loops, entity identities or Store
versions are introduced.

## Hardware evidence and open tests

On the reference GW15K-ETA-G20, mode 3 / 5,000 W produced about 5,030 W
battery discharge with internal PV still visible. Mode 5 / 1,000 W matched
load plus export approximately; mode 10 / 1,000 W gave 998 W net export.
Mode 8 settled to 16 W with 0.00 A shown. These point measurements do not
establish PV priority at the AC limit, mode-5 surplus charging, or the exact
35172 boundary with EV and external PV. Those remain explicit field tests.
The owner's observation that mode 12 stops PV excludes it from Hybrid 2.0.
See [the decision table and evidence](../HYBRID_2.md).

The existing command sensor exposes a read-only `mapping_preview` with
assumptions and input status. `scripts/preview_ems_mapping.py` replays every
CSV/TSV/pasted EMHASS plan row without contacting Home Assistant or GoodWe.
The selected Hybrid 2.0 controller still sends commands; the diagnostic
preview does not disable automatic control.

## Validation

Regression coverage includes grid-first boundaries, planned watts, explicit
Pause, fresh local load/EV validation, cloud isolation, EV start/stop,
manual modes 1–12 and the shared preview model. Release gates require
Quality, HACS, hassfest and the desktop Chromium / iPad WebKit / iPhone
WebKit matrix on the final candidate. Automated tests validate software
behavior; they do not replace the open hardware tests above.
