# GW EnergyPilot v1.2.0-beta.3

**Channel:** Beta prerelease

This prerelease adds an operator-selectable fixed household load forecast while
preserving the complete beta.2 mobile, SEMS, plan-timing and diagnostic base.

## EMHASS load forecast

- Settings → EMHASS adds **Load forecast · AUTO / CUSTOM**.
- AUTO is the default for upgrades and continues to use the existing GoodWe
  load register 35172 plus Recorder-history forecast.
- CUSTOM reveals a fixed-watt input. Its initial value is 700 W and its saved
  value remains available after switching back to AUTO.
- CUSTOM replaces only `load_power_forecast` in the final runtime request to
  `/action/dayahead-optim`.

The generated list uses an existing runtime `prediction_horizon` when one is
already present. Otherwise its number of steps is derived from EMHASS
`delta_forecast_daily` and `optimization_time_step`. A one-day horizon at a
15-minute step sends exactly 96 values.

## Compatibility and rollback

- Existing runtime SOC, price forecasts, battery limits and unrelated
  parameters remain intact.
- Returning the switch to AUTO is the complete rollback; no EMHASS config.json
  load-forecast method is rewritten.
- Existing config entries, entity IDs, device identity, Recorder history and
  persistent Store keys are unchanged.
- Local Modbus remains the only EMS and minimum-SOC write/read-back transport.

## Frontend cache

The complete active frontend graph uses cache boundary
`1.2.0-beta.3-load-forecast1` so upgraded sessions load the new conditional
CUSTOM field immediately.
