# GW EnergyPilot v1.3.0-beta.8

**Channel:** Beta prerelease

**Status:** Prepared candidate; not published.

## House self-consumption during EV charging

Hybrid 2.0 keeps ordinary house self-consumption available while the EV
charges. A positive battery plan with neutral grid (+700 W and 0 W, for
example) remains self-use. Net charging follows the EMHASS battery watts
instead of replacing them with maximum mode-2 assistance.

| Ready EMHASS plan | Without EV | EV charging |
|---|---|---|
| Battery charging and grid import, both outside their deadbands | Mode 11, bounded battery watts | Same mode and watts |
| Non-neutral battery, grid inside its deadband | Mode 1, 0 W | Mode 9, measured EV watts |
| Charging alongside planned PV export | Mode 10, bounded grid target | Mode 9, measured EV watts |
| Battery neutral | Mode 8 Hold, 0 W | Mode 8 Hold, 0 W |
| Battery discharge with non-neutral grid | Normal Hybrid | Mode 8 Hold, 0 W |

Mode 9 controls import at the house meter. Import equal to EV load lets
GoodWe balance ordinary house use and PV locally; the battery may charge or
supply that house. EnergyPilot refreshes this reference every 15 seconds
through its existing controller lock and Modbus path. It does not control
charger current or add a competing power-feedback controller.

Self-use requires a measured EV power sensor with explicit units and a valid
report no older than 30 seconds. Missing/stale/future/invalid or out-of-range
references select Hold; missing activity telemetry is not a confirmed EV stop.
Missing/non-ready/suspended plans during EV charging also select Hold. A valid
persistent plan can supply missing publication. Confirmed EV stop with native
orchestration requests Hold immediately and retains the fresh-plan/retry gate.
Without EV, missing inputs retain the existing waiting behavior.

Existing Battery/Grid/Hybrid selections, manual commands, config/storage
identity and Modbus register semantics remain unchanged. Mode 2 remains
available manually. The dashboard distinguishes house self-consumption,
planned charging and Hold. Live self-use can differ from forecast battery
power/SOC, and inverter/BMS limits remain authoritative. See
[Hybrid 2.0 policy and field evidence](../HYBRID_2.md).

## Validation

Candidate checks cover the supplied field case, exact deadband boundaries,
planned watts, EV start and plan transitions, 15-second updates, unit/time
validation, missing inputs, persistence, EV stop, manual ownership and unload.
Repository Quality and the three-profile
frontend matrix must pass before release, together with HACS and hassfest on
the exact final head.

Automated tests do not replace synchronized hardware validation of the
periodic mode-9 reference.
