# GW EnergyPilot v1.3.0-beta.8

**Channel:** Beta prerelease

**Status:** Prepared candidate; not published.

## EV Hold outside planned net charging

Hybrid 2.0 now distinguishes PV-only battery charging from planned grid
charging. Beta.7 used any negative battery plan as permission to buy maximum
grid energy, including periods when EMHASS intended only PV charging.

| Ready EMHASS plan | Without EV | EV charging |
|---|---|---|
| Battery charging and grid import, both outside their deadbands | Mode 2, configured maximum | Mode 2, same maximum |
| PV-only charging around zero grid | Mode 1, 0 W | Mode 8 Hold, 0 W |
| Charging alongside planned PV export | Mode 10, bounded grid target | Mode 8 Hold, 0 W |
| Battery neutral | Mode 8 Hold, 0 W | Mode 8 Hold, 0 W |
| Battery discharge | Normal Hybrid | Mode 8 Hold, 0 W |

For the supplied `P_batt = -1.33 kW`, `P_grid = -29 W` case, EV start now
changes mode 1 to mode 8. A later explicit grid-charge window selects mode 2;
returning to a PV-only window selects Hold again while EV charging continues.
EMHASS still owns economic timing; no independent price threshold or charger
control is introduced.

Missing/non-finite required plan inputs wait without a new EMS write. A valid
persistent plan can supply missing publication. EV neutral/discharge Hold
still needs no grid target. The common grid gate also fixes beta.7's invalid
neutral/discharge command conversion when grid data is unavailable.

Existing Battery/Grid/Hybrid selections, manual commands, optimizer readiness,
EV-stop fresh-plan protection, config/storage identity and Modbus register
semantics remain unchanged. Mode 2 still requests a maximum allowance; actual
charging and SOC can exceed the EMHASS forecast. See
[Hybrid 2.0 policy and field evidence](../HYBRID_2.md).

## Validation

Candidate checks cover the supplied field case, exact deadband boundaries,
EV start and plan transitions, missing data, persistent fallback, readiness,
manual ownership and compatibility. Repository Quality and the three-profile
frontend matrix must pass before release, together with HACS and hassfest on
the exact final head.
