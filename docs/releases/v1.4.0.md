# GW EnergyPilot v1.4.0

**Channel:** Stable

Production promotion of v1.3.0-beta.11. Runtime behavior is unchanged from
that candidate; the manifest, complete frontend cache boundary and dashboard
presentation now identify v1.4.0 Stable.

## Included in this production release

- Compact mobile controls, enlarged touch targets, responsive Power overview,
  solar-production graphs and the existing user-controlled live-flow motion.
- Hybrid 2.0 PV-priority charging and opt-in Hybrid 3.0 excl. EV, with the
  English/Dutch six-scenario explanation in the dashboard.
- Hybrid 3.0 measurement freshness/skew checks, protective Hold and recovery,
  bounded direct local EMS readback and explicit execution-history diagnostics.
- EV-stop Hold until a new successful optimization and fresh live battery and
  grid plans, while retaining existing manual ownership and plan resilience.

## Upgrade

Install v1.4.0 through HACS and restart Home Assistant. This normal/latest
release is offered without enabling prereleases. Existing strategy selections,
EMHASS settings (including CUSTOM forecasts), SOC profiles, entity identifiers
and stored history are preserved. No configuration or storage migration is
introduced by this promotion.

Hybrid 3.0 remains an explicit choice under **Settings → GoodWe → Automatic
control strategy → Hybrid 3.0 excl. EV**. An upgrade does not select it.

## Retained field-validation boundaries

The production channel does not remove the documented Beta status of optional
Hybrid 2.0/3.0 and SEMS+ features. Mode-5 surplus-PV behavior, the EV/external-PV/
local-load measurement boundary, transient response and actual Tibber reward
impact still require synchronized installation evidence. Prior mode-5/Hold
oscillation is not claimed to be physically eliminated. Readback confirms the
EMS mode/setpoint, not settled physical power. See [Hybrid 3.0](../HYBRID_3.md).

## Validation

The release gates cover Python compilation, the unit/contract suite,
repository and stable-tag validation, JavaScript syntax and frontend
architecture checks, and desktop Chromium, iPad WebKit and iPhone WebKit
regressions. GitHub Quality, HACS and hassfest must pass on the final release
commit before publication. Software/browser checks do not replace physical
GoodWe or iPhone Safari/Companion acceptance.
