# GW EnergyPilot v1.3.0-beta.7

**Channel:** Beta prerelease

## Hybrid 2.0 charge-window correction

Hybrid 2.0 now selects mode **2** at configured maximum control power whenever
the finite, ready EMHASS `P_batt` plan explicitly requests charging below the
Battery Hold deadband. `P_grid` no longer has to show planned import.

This fixes the supplied live beta.6 case:

```text
EV active
P_batt = -1.33 kW
P_grid = -29 W
beta.6 expected mode = 1
beta.7 expected mode = 2 at configured maximum power
```

The EV's 11 kW consumption was absent from EMHASS `P_Load`, leaving planned
`P_grid` near zero even though the actual house load was 11.1 kW. Using
`P_grid` as a second mode-2 gate therefore defeated the purpose of Hybrid 2.0.

A neutral, exporting or unavailable `P_grid` now still permits mode 2 during
an explicit battery charge plan. Outside that charge window, Hybrid 2.0 keeps
the existing Hybrid branches and still waits when those branches require
missing `P_grid`. EV neutral/discharge plans remain mode 8 Hold. Optimizer
readiness, persistent-plan fallback, EV-stop freshness, manual mode ownership,
registers and EMS write order are unchanged.

Mode 2 remains a maximum grid-assistance allowance with PV priority. It does
not guarantee actual import or charge power; BMS and inverter limits remain
authoritative. Actual charging and SOC can exceed the EMHASS forecast.
