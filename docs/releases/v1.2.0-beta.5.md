# GW EnergyPilot v1.2.0-beta.5

**Channel:** Beta prerelease

This prerelease applies the physically measured beta.4 winner to the complete
EnergyPilot button surface for the iOS Home Assistant Companion missing-click
defect. It does not change GoodWe, EMS, EMHASS or Battery Saver semantics.

## Bounded touch-click recovery

One adapter is installed on the existing panel ShadowRoot. For a primary touch
that begins and ends on the same enabled control and moves no more than 12 px:

1. EnergyPilot waits 120 ms for the native click;
2. a timely click proceeds unchanged and cancels the timer;
3. if click is absent, the same element's existing `.click()` route is invoked;
4. one later physical click for that fallback is suppressed.

The adapter covers native buttons throughout the permanent control surface,
Settings, dashboard layout, card/window controls, diagnostics, plan/history
views and modals. Checkbox/radio menu controls and labels, native `summary`
controls and semantic buttons use the same route.

## Safety boundaries

- Pointer listeners are passive; the adapter never captures a pointer, cancels
  a pointer event, blocks vertical scrolling or writes scroll position.
- Movement beyond 12 px and `pointercancel` never schedule an action.
- Disabled, disconnected, changed and secondary-touch targets are rejected.
- Recovery calls no service or WebSocket API directly. Operational actions
  still pass through their existing Lit pending/acknowledgement/error state
  machine; forms, menu changes and historical presentation controls retain
  their existing handlers.
- Mouse, pen, keyboard and unrelated programmatic activation keep their native
  behavior.
- The five numbered `[data-beta-control]` methods stay outside the adapter so
  they remain a raw physical-device comparison.

## Validation and field follow-up

The desktop Chromium, iPad WebKit touch and iPhone WebKit touch matrix removes
native click after pointerup and proves exactly one operational service call,
late-click deduplication, movement/cancel rejection, layout-menu open/close, a
menu switch, Beta Tests navigation and Settings navigation. The complete
existing frontend and repository suites remain release gates.

Physical Home Assistant Companion verification remains required because
Playwright WebKit cannot reproduce the branded WebView defect. After upgrade,
test ordinary dashboard/menu taps first and export the Beta Tests JSON if a tap
still fails; it now includes `production_touch_fallback` metrics.

The complete active frontend graph uses cache boundary
`1.2.0-beta.5-touch-fallback1`.
