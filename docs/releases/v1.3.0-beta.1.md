# GW EnergyPilot v1.3.0-beta.1

**Channel:** Beta prerelease

This beta makes EnergyPilot easier to operate, understand and discover without
changing its GoodWe, EMS or EMHASS control semantics.

## Compact EnergyPilot controls

- Operational controls now occupy one normal-width, fixed dashboard card after
  the four live power cards instead of an oversized full-width area.
- The four battery quick actions and Optimize remain directly available.
- EMHASS strategy, Battery Strategy and manual EMS use compact native
  disclosures while preserving their permanent Lit nodes and exact action
  paths.
- Existing saved dashboard layouts gain the fixed controls card without
  resetting the remaining card order or visibility preferences.
- Duplicate minimum/maximum SOC controls are removed from the EMHASS overview;
  Battery Strategy → Custom remains the single editor.

## Scoped live-flow motion

**Layout & visibility → Flow animations** is available again. It animates only
particles on finite active energy-flow connectors. Switching it off or using
`prefers-reduced-motion: reduce` stops the particles completely. All non-flow
animations, CSS transitions and modal backdrop filters remain disabled.

## Help and product documentation

- A localized **?** in the dashboard header opens the user guide in a new tab.
- Dutch Home Assistant sessions open `docs/HANDLEIDING_NL.md`; other sessions
  open `docs/USER_GUIDE.md`.
- Both guides cover installation, safe first validation, dashboard use,
  automatic strategies, battery profiles, planning, EV features,
  troubleshooting and support reports.
- The GitHub introduction now explains the complete EnergyPilot value chain:
  insight, price-aware planning, safety/strategy and verified local execution.

## Compatibility and safety

GoodWe registers, EMS mode/setpoint signs and write ordering, local-only control
ownership, EMHASS plan ownership, Battery Saver profile policy, entity unique
IDs, config-entry identity and persistent Store schemas are unchanged. SEMS+
remains optional Beta telemetry and never becomes a control transport. Stable
v1.2.0 remains the normal/latest production release.

## Validation

The release passes Python compilation, 505 repository unit tests, repository
invariant validation and the complete desktop Chromium, iPad WebKit touch and
iPhone WebKit touch stability matrix. The matrix verifies permanent control
identity, native scrolling, settings, charts/history, scoped motion and the
localized help link with a 44 CSS-pixel touch target.

The complete active frontend graph uses cache boundary `1.3.0-beta.1`.
